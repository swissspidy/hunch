On-device personalization for websites

Recommendations that stay on the reader’s device.

Hunch ranks related posts, “for you” lists and “since your last visit” digests in the visitor’s browser. Your build publishes a vector for every item; the browser does the arithmetic. There is no server-side profile, no third party, and nothing about the visitor leaves the device.

Try the demo Get started

Hunch is pre-release: the first version, 0.1.0, is on its way to npm and the WordPress plugin directory. Until then, try the demo or build it from the source.

How it works

  1. Build

    hunch build reads your feed, JSON, sitemap or your own loader, and embeds every item with a pinned open model, EmbeddingGemma by default. Rebuilds embed only what changed.

  2. Publish

    It writes a small manifest.json and one binary shard per section: static files next to your site, about 260 KB gzipped per 1,000 items. Any host or CDN will do.

  3. Rank in the browser

    Web components take your server-rendered lists and swap their entries, slot for slot, for the items closest to what the reader is reading, or has read. Nothing moves on the page.

Private by design

Personalization is built from what the visitor reads on your site, and that history stays in your site’s own storage in their browser.

  • Nothing without consent. Until your consent hook says yes, nothing is stored, not even an empty database.
  • No profile in any request. Pages fetch the manifest and shards, the same files for everyone. The browser tests check it.
  • No profile at rest. Only the signals are kept; the profile is derived on each page, so a new model needs no migration.
  • The visitor decides. Pause, export and forget, built in, with a block for your page.

Small, fast and still

The ranking runs no model: cosine similarity over int8 vectors, a recency boost and diversity, on a WebAssembly SIMD kernel with a JavaScript fallback.

Fits your stack

Any site

Build the vectors from your feed, then wrap the list you already render.

npx hunch build \
  --source https://example.com/feed.xml \
  --out public/hunch
<hunch-related manifest="/hunch/manifest.json"
               item="sourdough-starter">
  <ol>
    <li data-hunch-slot>…</li>
  </ol>
</hunch-related>

Astro

The integration embeds the pages astro build wrote and loads the components. 

import hunch from '@swissspidy/hunch/astro';

export default defineConfig({
  integrations: [hunch({ include: ['/blog/*'] })],
});

WordPress

No Node on the server and no CI: posts are embedded in the editor’s browser on publish, and PHP writes the same files as the CLI. Related posts, a “For you” block and the visitor’s controls.

Try it in WordPress Playground Download the plugin

The download is the latest build from main. In WordPress Playground, a demo site with the demo’s articles runs in your browser, its posts already embedded. The plugin’s readme explains the rest.

JavaScript

Or call the client yourself.

import { Hunch } from '@swissspidy/hunch';

const hunch = await Hunch.load({
  manifest: '/hunch/manifest.json',
  consent: () => myConsent.allows('personalization'),
});
await hunch.recommend({ n: 4 });

See it work

The demo is a small publication. Open an article: its “Related” list is ranked in your browser. Turn on personalization, read a few articles, and “For you” follows.
