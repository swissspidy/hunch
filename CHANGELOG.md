# @swissspidy/hunch

## 0.1.0

### Minor Changes

- [#5](https://github.com/swissspidy/hunch/pull/5) [`9bbda40`](https://github.com/swissspidy/hunch/commit/9bbda40a94e8a71747cb96e55e959663d99c1707) Thanks [@swissspidy](https://github.com/swissspidy)! - Astro integration: `@swissspidy/hunch/astro` builds the catalog from the pages `astro build` emitted (selected with `include`, `exclude` and `page`, or replaced with `items`), writes `manifest.json` and the shards into the build output with an incremental embedding cache in `node_modules/.cache/hunch`, and loads the web components on every page with the manifest preset. The components now take their manifest from `window.HunchConfig.manifest` when they have no `manifest` attribute, and the ES module build of the components applies `window.HunchConfig` too.

- [#22](https://github.com/swissspidy/hunch/pull/22) [`b6ea393`](https://github.com/swissspidy/hunch/commit/b6ea393bf9595c0cd8622c5a90f4b3270c8a4043) Thanks [@swissspidy](https://github.com/swissspidy)! - List components fire `hunch:click`, which bubbles, when a slot is clicked: `detail` is `{ id, url, position, list, personalized }`. With `hunch:ready` (an impression), a site can count recommendation clicks in its own analytics. Hunch sends neither event anywhere.

- [#21](https://github.com/swissspidy/hunch/pull/21) [`e4f2aa8`](https://github.com/swissspidy/hunch/commit/e4f2aa899eafd60a4cca72018699fdca38ec17b4) Thanks [@swissspidy](https://github.com/swissspidy)! - `<hunch-for-you>` slots can say why an item is there and let the visitor hide it. A `[data-hunch-because]` element gets "Because you read …" (the `because` attribute sets the text) when the profile placed the item and the item it names is close to it (`because-min`, default 0.35). A `[data-hunch-hide]` button, shown only with consent, records a `hide` signal; the list then ranks again, focus moves to the same slot's link, and a `[data-hunch-announce]` live region gets its `data-message`. Each `why.because` entry now has `similarity`, its cosine similarity to the recommended item.

- [#1](https://github.com/swissspidy/hunch/pull/1) [`5ea1be8`](https://github.com/swissspidy/hunch/commit/5ea1be831de9f06bfba776e9db93a14451d87f70) Thanks [@swissspidy](https://github.com/swissspidy)! - First release (milestone 1): `hunch build` embeds a catalog from JSON, RSS/Atom, a sitemap or a loader module with EmbeddingGemma (or a pluggable provider) into `manifest.json` and int8 vector shards, incrementally. The dependency-free client ranks related items in the browser with `const hunch = await Hunch.load({ manifest })` and `await hunch.related(id)`, and `<hunch-related>` fills server-rendered slots with them without layout shift.

- [#1](https://github.com/swissspidy/hunch/pull/1) [`5ea1be8`](https://github.com/swissspidy/hunch/commit/5ea1be831de9f06bfba776e9db93a14451d87f70) Thanks [@swissspidy](https://github.com/swissspidy)! - Personalization (milestone 2): with the site's consent hook (`consent`, `Hunch.configure()` or `window.HunchConfig`), the client records view, click, dwell, follow and hide signals in IndexedDB, derives a profile from them on every page, and ranks "for you" with `recommend()` and `rank()`. `explain()` and every result's `why.because` say which of the visitor's items a recommendation leans on. `pause()`, `resume()`, `export()` and `forget()` are the visitor's controls. New components: `<hunch-for-you>` and `<hunch-page>`.

- [#12](https://github.com/swissspidy/hunch/pull/12) [`49514d5`](https://github.com/swissspidy/hunch/commit/49514d5f572f01d2fe7c38d6280da31229a56bf9) Thanks [@swissspidy](https://github.com/swissspidy)! - EmbeddingGemma's q4 weights now load `model_no_gather_q4`, the q4 file browsers can run. `model_q4` needs an ONNX Runtime operator (`GatherBlockQuantized`) that browsers lack, so `createQueryEmbedder(manifest, { dtype: 'q4' })` failed in browsers. The manifest names the file in an optional `model.file` field, and it is part of the space and the embedding-cache key, so a catalog built with `--dtype q4` before this release is re-embedded (q8 catalogs are unchanged).

- [#4](https://github.com/swissspidy/hunch/pull/4) [`c2fe6e5`](https://github.com/swissspidy/hunch/commit/c2fe6e5ce6373c46ee7d8ab6f8dee2fbdeef8e82) Thanks [@swissspidy](https://github.com/swissspidy)! - Free-text search on the device: the build publishes the model's query prompt (`model.queryPrompt`), `hunch.search(vector, options)` ranks the catalog against a query vector (optionally blended with the profile), and `@swissspidy/hunch/query` embeds the query in the browser with the catalog's own pinned model through Transformers.js (or in plain JavaScript for `hash` catalogs). The query text never leaves the device.

- [#17](https://github.com/swissspidy/hunch/pull/17) [`c4cedb5`](https://github.com/swissspidy/hunch/commit/c4cedb5492d4acc5e1406ace0e1536e827b839bc) Thanks [@swissspidy](https://github.com/swissspidy)! - Shards keep each item's prior, publication time and section in binary columns, list the item ids in a small JSON header, and keep the rest of each item's metadata (title, URL, tags, date, image) as separate JSON that the client decodes only for the items a call returns ([ADR 0011](https://github.com/swissspidy/hunch/blob/main/docs/adr/0011-shard-columns.md)). Loading 100,000 items in Chromium takes about a third less main-thread time than with one JSON header per shard, the JS heap after loading is 85% smaller (33 MB → 5 MB), and recency no longer depends on how the visitor's browser parses dates. On plain-HTTP pages, where `crypto.subtle` is missing, `fetch()` checks each shard's hash as Subresource Integrity, so a custom `fetch` must honour `init.integrity`. `decodeShard()` from `@swissspidy/hunch/format` returns the columns (`ids`, `prior`, `time`, `sections`, `section`), `count`, `version` and `item(i)`, alongside `items`.

- [#13](https://github.com/swissspidy/hunch/pull/13) [`fcdb4e5`](https://github.com/swissspidy/hunch/commit/fcdb4e54d93a3b271dfbee445512c50441da5b66) Thanks [@swissspidy](https://github.com/swissspidy)! - Ranking is about 11× faster in Node and 5× faster in a throttled browser on a 100,000-item catalog (ADR 0010). The client keeps the loaded catalog as columns (one contiguous block of vectors, and typed arrays for norms, priors, dates and sections) and computes similarities with a 332-byte WebAssembly SIMD kernel that splits the query into two int16 vectors and sums exactly in integers. Results match the previous release to within 1e-8. Where WebAssembly SIMD is unavailable (older browsers, a Content Security Policy without `'wasm-unsafe-eval'`) or the catalog is float32, a JavaScript kernel gives the same results. New: `Hunch.load({ kernel: 'js' })` forces it, and `hunch.kernel` says which one runs.

- [#3](https://github.com/swissspidy/hunch/pull/3) [`1b9b703`](https://github.com/swissspidy/hunch/commit/1b9b7034d3d141472b1b87a0fab57395f0c92b4c) Thanks [@swissspidy](https://github.com/swissspidy)! - "Since your last visit": the client records visits with consent (`visit()`; a visit ends after `visitGapMinutes` without activity), and `sinceLastVisit()` ranks the items published since the previous one. `recommend()` accepts `after`. The new `<hunch-digest>` component fills server-rendered slots with them, and adds a one-line summary from the browser's built-in Summarizer where its on-device model is available. The Summarizer helpers are in `@swissspidy/hunch/digest`.

- [#23](https://github.com/swissspidy/hunch/pull/23) [`a458c98`](https://github.com/swissspidy/hunch/commit/a458c9858cfa05f6207dd3407616dd181793afb8) Thanks [@swissspidy](https://github.com/swissspidy)! - Shards stay the same when the catalog changes, so returning readers download only what changed. Priors are counted from the end of the site's order over a power of two, so a new post at the top changes no other item's prior. A section's items are spread over buckets by a hash of their id (sections of more than half of `maxShardItems` get several shards), so an edit or a new post rewrites one shard. The format is unchanged.

### Patch Changes

- [#7](https://github.com/swissspidy/hunch/pull/7) [`2b082bb`](https://github.com/swissspidy/hunch/commit/2b082bb5769d44b19aa667b1a3ce03b0e813763a) Thanks [@swissspidy](https://github.com/swissspidy)! - Every public export has a doc comment, and the API reference is generated from them and published with the demo at https://swissspidy.github.io/hunch/api/. The types that public signatures already used are now exported too: `RankingOptions` (from `@swissspidy/hunch`), `SitemapOptions` (from `/build`) and `TransformersModel`, `TransformersTokenizer` and `TransformersTensor` (from `/query`).

- [#6](https://github.com/swissspidy/hunch/pull/6) [`e8d6684`](https://github.com/swissspidy/hunch/commit/e8d6684582ab18383ec3c82b7ccf5ac5c0821b73) Thanks [@swissspidy](https://github.com/swissspidy)! - Large catalogs no longer block input while they load and rank: the client scores candidates in short slices and yields to the page between them (with `scheduler.yield()` where the browser has it, otherwise a new task), and decodes each shard in a task of its own. Results are unchanged, except that items with exactly equal scores now always come in manifest order instead of the order their shards arrived in. Ranking is also faster, because only the best candidates are kept in order instead of sorting all of them. No API or option changes (ADR 0008).

- [#7](https://github.com/swissspidy/hunch/pull/7) [`2b082bb`](https://github.com/swissspidy/hunch/commit/2b082bb5769d44b19aa667b1a3ce03b0e813763a) Thanks [@swissspidy](https://github.com/swissspidy)! - The list components no longer drop keyboard focus: while a slot holds focus, `<hunch-related>`, `<hunch-for-you>` and `<hunch-digest>` wait for it to leave before replacing the slots. An `aria-label` on a slot or its link that contains the fallback item's title now gets the new item's title, so the link's accessible name matches what it shows.

- [#7](https://github.com/swissspidy/hunch/pull/7) [`2b082bb`](https://github.com/swissspidy/hunch/commit/2b082bb5769d44b19aa667b1a3ce03b0e813763a) Thanks [@swissspidy](https://github.com/swissspidy)! - Signals of a kind the client doesn't know (written by a newer release) are no longer counted as views or pruned by age: they are kept as they are and ignored (ADR 0009).
